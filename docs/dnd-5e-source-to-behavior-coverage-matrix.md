# 第一版来源到行为覆盖矩阵

## 目的与完成标准

本矩阵是第一版设计基线，也是实现与发布门禁。它回答每类规则或模组结构由哪项 Skill 主责、何时激活、读取或改变什么权威状态、玩家或维护者能观察到什么结果，以及失败时如何安全处理。

当前行粒度为源书章节、规则族、标准模组结构和跨领域主持场景，状态均为“已分配”。开发构建工具链必须在提取后把每行扩展为语义规则章节和规则实体条目，并将状态推进为：

- 已分配：已经确定稳定主责、协作方、状态、行为、失败路径和验收场景。
- 已实现：对应 Skill、支持组件和状态契约已经提供可运行行为。
- 已验证：来源定位、代表性验收场景和异常路径全部通过。
- 待复核：来源缺失、提取歧义、规则冲突、职责冲突或授权条件尚未解决。

默认规则、条件规则和标准模组必需结构只有在全部叶级行达到“已验证”后才算覆盖。任何未分配主责、职责重叠未说明、必需行处于待复核或来源授权不完整的情况都阻止公开发布。

## Issue #4 交付边界

[GitHub Issue #4](https://github.com/Hanray-Zhong/dnd-skill/issues/4) 负责把本矩阵中的三宝书章节级设计基线首次完整扩展为可交付的规则章节库，而不是只用单份样本证明查询链路：

- 构建输入必须是已经固定版本与哈希的《玩家手册》v1.72、《城主指南》v1.1 和《怪物图鉴》配图版 v1.3.2；纯文字怪物图鉴与词表只能交叉核对，不能补写或覆盖权威内容。
- 开发构建工具链必须批量生成全部范围内语义规则章节、规则实体 Markdown、可查询索引、来源元数据、内容哈希和叶级覆盖记录；每个源书章节与目录实体都必须有已生成或明确阻塞的对应记录。
- 默认规则缺失、双栏阅读顺序错误、跨页主题断裂、表格或侧栏丢失、页码不可追踪、交叉引用断裂及输入哈希变化都必须产生可观察失败，不能以模型常识补全。
- 运行中的十一项 Skill 只能读取已经生成并固定版本的 Markdown、索引与来源元数据；开发构建工具链和 PDF/XLSX 解析器不得注册为 Skill、不得由主持门面调用，也不得成为运行时依赖。
- 本地预览包必须携带生成资产并能在开发参考文件不可用时完成规则查询；原始 PDF、XLSX、提取缓存和临时中间文件不得进入包内。公开分发仍须通过来源授权和 Issue #33 的发布门禁。
- Issue #5 继续负责规则实体的具体例外，Issue #6 继续负责可执行公式目录；它们消费 Issue #4 生成并可追溯的规则资产，不替代完整内容构建。

## 所有权规则

- 主责 Skill 定义该行的领域语义；协作 Skill 只能提供规则、投影或状态服务。
- dnd-5e 是唯一玩家主持门面和最终知识投影边界，不作为规则内容的兜底主责。
- dnd-5e-campaign-state 是唯一持久写入边界，不代替其他 Skill 作领域判断。
- 规则与模组行为行必须使用稳定 Skill 标识作为主责；构建、计算和投骰等系统行可以使用明确命名的支持组件作为主责，但这些组件不计入 Skill 目录。
- 一项来源同时影响多个领域时仍指定一个主责 Skill，并在协作列记录其他参与方。

## 叶级扩展要求

开发构建工具链必须为下列内容生成叶级覆盖行；三宝书范围不得以代表性样本、首个章节或少量实体代替完整枚举：

- 每个语义规则章节；
- 每个法术、怪物、魔法物品、状态和其他规则实体条目；
- 每个被纳入第一版的可选规则和条件规则；
- 标准模组样本中的章节、地图、区域键、NPC、遭遇、任务、线索、奖励、随机表和专属实体类别；
- 每项世界视觉参考与地图模型；
- 每项确定性公式和查表规则。
- 每个角色字段的变更权限及其角色选择窗口；
- 每个工作区格式、状态 schema 与迁移契约；
- 每个已验证地图模型、空间规则算法和玩家战术投影契约。

同构实体可以引用共同验收场景，但必须分别保留来源、内容哈希、激活条件、主责 Skill 和验证状态。覆盖矩阵生成失败、存在孤立来源、存在没有来源的行为或出现循环职责依赖时，构建必须失败。
